# kitelev/exoas-product-kitelev

`exo__AssetSpace` дескриптор **пространства продукта** «личный ассистент Андрея»
(`@KITELEV_EXOASSISTANT_BOT`). Точка монтирования `assetspaces/kitelev/exoas-product-kitelev/`,
namespace-анкер `$product-kitelev`.

Держит единицы работы, рождённые из промахов ассистента: `ems__Bug`, заведённые по явной
команде пользователя. Заводится RFC `dd6a6e0b-fc01-45fc-a284-66c0bc330290` §VL#3′ —
**по пространству на продукт, а не одно общее**: баг несёт ссылку на реплику своего
пользователя, поэтому общее пространство стало бы утечкой при появлении второго продукта.

## Монтируется в четырёх профилях

- `$$kitelev-my` — бот-писатель (`~/vaults/vault-bot-kitelev`),
- `$$kitelev-exodev` — автономная петля разработки (`~/vaults/vault-exodev`),
- `$$kitelev-my-full` / `$$kitelev-exodev-full` — зеркала рабочих копий Mac.

⛤ Присутствие в `exo__Profile_includes` каждого из них — **не косметика**: `apply-profile`
работает strict-replace'ом, поэтому профиль без дескриптора сносит пространство при первом
же применении, а демон-писатель падает **молча** (прецедент 17 ч / 25 попыток).

`dependsOn` → `exoas-public`: там живёт TBox `ems__` (класс `ems__Bug`), без него инстансы
пространства не резолвятся.
